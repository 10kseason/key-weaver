# E+ Full-field + taps

Status: experimental, opt-in, included in v1.4.0. This follows the request for substantially
more simultaneous taps at existing timings. It applies to all 1K–18K sources
converted to 8K or 10K. Plain E remains unchanged; the preceding E+ v2 lane
algorithm is shared by both targets, and existing 10K behavior is retained.

## Use and behavior

Select **NK2 (Experimental)** → **E+ - Full-field + taps** → Target **8** or **10**.
CLI: add `--nk2-e-tap-boost` to the existing E+ command:

```text
build/KeyWeaver.exe input.osu --engine nk2 --target 10 --nk2-mode faithful --nk2-search phrase --nk2-phrase-support --nk2-phrase-dense-ln --nk2-phrase-source-ln --nk2-e-fullfield --nk2-e-tap-boost --report conversion.json --pattern-hotspot-report new-hotspots.json
```

For 8K output, replace `--target 10` with `--target 8`. Output metadata, osu
`CircleSize`, lane reports and hotspot bins all follow the requested count.
The output key marker distinguishes 8K from 10K files. Native 8K input can also
be explicitly remixed to 8K. Other output counts remain unsupported by E+.

The converter finishes E and E+ v2 first, then appends taps. Every existing E+
note keeps its identity, target lane, head time, type, LN tail, raw data and
source-lane provenance. The new pass only uses head times of retained original
notes, including original LN heads. It adds no LNs, new times, tail-only anchors
or anchors supported only by generated notes. The exported list is sorted by
time, preserving existing same-time relative order.

This is a separate comparison choice, with `-fullfield-v2-taps-v2` filenames and
difficulty metadata. Omitting `--out` selects an unused filename. Existing
explicit output/report overwrite behavior is unchanged. Batch and BMS-family
routes are supported; BMS stays BMS. Hotspot sidecars remain single-input only
and identify the final result as `preset: "E+ taps"`. F boost remains separate.

## Bounds and safety

The observable target is a substantial increase on a chart with spare safe
space, with the entire preceding E+ population unchanged and original-source
safety passing. Safety failure is the stop condition: reject that destination;
if the final independent audit fails, remove this pass's additions.

- The total generated-note ceiling is `ceil(0.75 * retainedOriginals)`, including
  all notes already generated by E. This is a ceiling, not a guaranteed density.
- Each nonempty, floor-aligned 2-second window has a generated-note ceiling of
  `min(40, ceil(0.75 * retainedOriginalsInWindow))`, including existing additions.
  If local capacities sum above the remaining global budget, reserve proportional
  quotas using integer largest remainders (ties by window index). This prevents
  chronological iteration from exhausting all room before the ending. Unsafe
  or unusable quota is left unused; this is still a ceiling, not a density promise.
- At most three new taps per retained source timestamp, and no expanded chord
  above eight heads. Existing larger chords are left intact.
- Three chronological rounds try one tap per onset per round. Candidate work
  is bounded by three times the unique retained-source head count, with ten
  possible target lanes per candidate at 10K (eight at 8K). There is no randomness or time cutoff.
- Rank safe destinations by new-tap local count, new-tap global count, total
  local count, total global count, greater distance from occupied lanes in that
  chord, then lane index. All selected output lanes participate equally,
  including human-numbered 1/5/6/10 at 10K and 1–8 at 8K. Existing source
  placements are never moved by this pass.
- **User-authorized v2 policy:** only newly appended taps use
  `ceil(clamp(beatLengthMs / 2, 180, 500))` as their repeat guard. Gaps must be
  strictly greater than the guard, including at the exact boundary. Two new
  neighboring taps use the maximum of their guards across tempo changes.
  The latest timing point at or before the head supplies tempo; inherited SV
  points are ignored. Missing tempo and invalid/non-positive BPM points fall
  back to 500ms. Timing points with no inherited flag and a positive beat length
  are accepted; duplicate times use the last supplied point deterministically.
- Every preceding E+ note stays fixed. The pre-boost audit is still strict
  500ms; pairs of base notes retain that original policy and provenance rules.
  New taps must lie after any previous LN's inclusive tail. Collision, hold
  duration and source-LN coverage checks are never relaxed. Ordered per-lane
  indexes store values, so vector growth cannot invalidate safety references.
- Final independent safety receives exact IDs created by this pass. A prefix
  alone never grants an exemption; original notes and holds cannot use it.
  `createdLaneRepeats` counts violations of the effective policy.
  `strict500CreatedRepeats` counts all newly created repeats under the old
  strict policy; `tempoAllowedTapRepeats` records the explicitly allowed subset.
  Their difference must be zero for a passing final audit. A failure rolls back
  all newly appended taps and clears their authorizations.

Implementation: `src/nk2/e_tap_boost.*`, called after redistribution from
`applyEFullField` in `nk2_convert.cpp`. Optional `fullFieldTapBoost` report fields
give the starting population, retained originals, ceiling, actual added taps,
candidate/rejection counts, guards, strict/effective repeat counts, added counts
per lane (array positions 0–7 for 8K, 0–9 for 10K) and fallback status. When enabled, the existing
`fullFieldTransform` metrics are explicitly marked `analysisStage:
"before_tap_boost"`; final `placement`, safety and hotspot metrics include the
extra taps. The existing phrase-profile diagnostic uses the new local budget
only for this optional mode. Scores with different budgets are not direct
evidence of quality improvement. Legacy `placement.createdJacks` examines
neighbors in the global note sequence and may undercount lane repeats; it is
kept for compatibility. Use the independent lane-by-lane strict/effective
counters for this policy. When disabled, E/E+ report bytes are unchanged.

## GUI preset selection validation (2026-11-01)

The final Windows Release build passes all eleven CTest suites and GUI smoke.
The GUI exposes exactly E, E+ Full-field + taps, native, transform and harder,
with E selected by default. Smoke checks verify each choice's single/batch
command mapping and E+ gating to 8K/10K. Historical CLI recipes remain available.
The release script parses and its file manifest resolves, but no new release
archive was built. Native-window interaction and play quality remain unverified.

## 8K compatibility validation (2026-11-01)

Separate Release build `build-e-8k`, GNU 15.1.0 / Ninja, ONNX off. Fourteen
full-field groups and ten tap-boost groups pass, including 1K–18K sources to
both supported outputs, same-key 8K, dense 8K boundaries, empty/invalid inputs,
generated-LN preservation and all eight tap destinations. All eleven CTest
suites and GUI command smoke pass. CLI checks include explicit/automatic E
selection, batch determinism, 8K metadata, eight-element lane arrays, final
hotspot counts, unchanged BMS-family output and rejection of other E+ targets.

On one locally available native 4K chart, converted to 8K:

| Measurement | 8K result |
|---|---:|
| Original heads retained | 3,308 |
| Pre-boost E+ heads | 4,312 |
| Appended taps | 1,453 |
| Final heads | 5,765 |
| Holds before/after tap boost | 243 / 243 |
| Strict 500ms created repeats | 2,247 |
| Effective-policy violations | 0 |
| Collisions / LN overlaps | 0 / 0 |
| 8-second hotspot windows | 0 |

Final lane counts (human lanes 1–8) are `703, 700, 733, 760, 726, 732, 699, 712`;
appended counts are `192, 192, 178, 160, 176, 176, 194, 185`. All preceding E+
serialized objects remain unchanged, and every new object is a tap at an
original head time. All 2,247 strict repeats involving the new taps respect
the effective 180ms guard. Independent serialized counts match every diagnostic
bin. Repeated 8K chart/report bytes match. Plain E8 chart/report bytes match
the preceding executable. On that chart and the 7K LN sample, 10K E+ taps
chart/report/diagnostic bytes also match that executable.

Private chart/report artifacts are retained locally and are not distributed.
The fixed E+ redistribution work limit is still reached on this 8K conversion;
some groups retain E lanes. Eight output lanes
offer fewer safe destinations, so identical budgets do not guarantee the
same additions or feel as 10K. Thumb/finger assignment, chord feel and fatigue
remain playtest questions. Existing BMS export quantization is unchanged.

## Tap boost v2 10K validation (2026-11-01)

Separate Release build `build-e-stream-taps`, GNU 15.1.0 / Ninja, ONNX off.
Nine tap test groups cover the original preservation/budget cases and add:
inclusive beat guard boundaries; two-tap tempo transitions; invalid timing and
SV handling; no exemptions for originals/holds/unlisted generated notes;
collisions/LN tails; dense stream and chord-stream additions; opportunity on
all ten lanes; and a final-phrase budget regression. The full eleven-suite
CTest run and GUI smoke pass. Plain E/E+ serialized charts and reports match
the preceding executable; repeated v2 charts/reports/hotspot sidecars match.

| Original heads retained | 3,308 | 3,308 |
| Pre-boost E+ heads | 4,318 | 4,318 |

Here “dense” means at least 32 original heads in a floor-aligned 2s window
(61 windows); it is a reproducible measurement, not an automatic musical motif
classification. At 222–224s and 224–226s, extra taps rise from 3/6 to 23/23.
At 228–230s and 230–232s they rise from 5/8 to 12/17, and the last source head
at 232160ms also remains eligible. Its 188 BPM yields the 180ms floor.

New-layer lane counts (human lanes 1 through 10):

Every serialized preceding E+ object is present unchanged; every appended
object is a tap at a retained original head time. Independent and serialized
checks find zero collisions/LN overlaps, zero drops/retiming/changed holds,
and confirm that all 1,778 strict repeats involve new taps with gaps over
180ms. An independent serialized counter matches every hotspot bin and lane.
Private chart/report artifacts are retained locally and are not distributed.

The E+ redistribution work limit is still reached on this song; remaining
groups retain E lanes. This change adjusts only the later tap layer. Zero
hotspots at the requested 15pp threshold does not establish balanced finger
workload or pleasant chord shapes. Playtest especially 204–232s for thumb/index
participation, repeat feel, LN releases and fatigue at the same scroll speed.

## Prior tap boost v1 validation (2026-11-01, superseded policy)

Separate Windows Release build `build-e-taps`, GNU 15.1.0 / Ninja, ONNX off:
all eleven CTest suites and GUI smoke passed. Six new core test groups cover
substantial additions, inclusive 500ms/LN-tail boundaries, empty/full/capped
charts, generated-only onset exclusion, negative/extreme times, invalid inputs,
and full-converter preservation/determinism across all source counts 1–18.
CLI checks cover automatic/explicit routing, batch, BMS, distinct filenames,
missing-prerequisite rejection and final hotspot counts. The baseline compiler
warning in Classic `assignment.cpp` remains unrelated to this pass.

On a separate local native 4K comparison chart:

| Measurement | E+ v2 | E+ v2 + taps |
|---|---:|---:|
| Total heads | 2,743 | 3,300 |
| Generated heads relative to 2,076 originals | 667 (32.1%) | 1,224 (59.0%) |
| Holds | 108 | 108 |
| 8-second hotspots | 0 | 0 |

The pass added 557 taps. All preceding E+ objects were present unchanged in the
serialized chart, and every extra object was a tap at an existing original
head time. Independent source-LN safety passed with zero collisions, LN
conflicts, created repeats, drops, retiming or changed LN durations. Repeated
chart/report/diagnostic bytes matched; disabled E+ chart/report bytes matched
the preceding build; an independent serialized counter matched hotspot counts.
Existing chart-folder files were unchanged during validation.

Actual chord feel, fatigue and difficulty still require playtesting. Dense
inputs could admit few or no additions under the v1 strict 500ms constraint.
Existing BMS export timing quantization is outside the new pass's contract.
